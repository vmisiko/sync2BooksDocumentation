This is the architecture behind the eTIMS pages in this section: how Sync2Books acts as a
**Trader Invoicing System (TIS)** and transmits fiscal data to **KRA eTIMS** over the **OSCU**
path. It is the same document submitted to KRA for third-party integrator certification, so it
describes the system as built rather than as planned — anything not yet implemented is confined
to its "Planned enhancements" section.

## What it covers

## Who it's for

<Note>
  You do **not** need this document to integrate. Start with
  [eTIMS Compliance Overview](/etims-overview) and
  [Get Started with eTIMS](/etims-getting-started) instead.
</Note>

It's written for reviewers and technical evaluators — KRA certification, a tax or security
audit, or a prospective partner's due diligence — who need to see how fiscal data reaches KRA
and how taxpayer credentials are held.

## Source and versioning

The PDF is generated from a markdown source kept with the compliance service, so the document
and the code stay in the same review loop. It is rebuilt with:

```bash
python3 scripts/build-architecture-pdf.py
```

Don't hand-edit the PDF — edit the markdown and rebuild, or the two drift apart.
