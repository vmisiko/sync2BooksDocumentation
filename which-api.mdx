Sync2Books is **two separate products** that happen to share a dashboard, an API key, and a base URL. They solve different problems, have different data models, and — as of today — are documented and referenced separately. Most of the confusion in these docs in the past came from mixing the two together, so start here.

## Side by side

|  | **Accounting API** | **Compliance API (eTIMS)** |
|---|---|---|
| **Answers the question** | "How do I get this expense/bill/invoice into my customer's books?" | "How do I make this sale legal under Kenyan tax law?" |
| **The external system** | An accounting package your customer already uses (QuickBooks, Xero, Sage, Dynamics, Odoo) | The Kenya Revenue Authority's eTIMS network (via an OSCU device) |
| **How you connect a company** | OAuth, via the [Link component](/link-integration) or an `authUrl` | KRA PIN + device serial, via the **dashboard** (see [Connecting a Company](/etims-provisioning)) |
| **Core objects** | Expense, Bill, Invoice, Bill Payment | Catalog item, Sale, Credit note, Branch |
| **Geography** | Anywhere | Kenya only |
| **Reference docs** | [Accounting API](/api-reference) | [Compliance API](/etims-api-reference) |

## What's shared

Both products sit behind the same [authentication](/concepts/authentication) (your `X-API-Key`), the same [sync model](/concepts/sync-model) (queue a write, get a `syncBatchId`, confirm the result), and the same [company](/concepts/companies-and-connections) as the unit you scope requests to. Learn those three concepts once — you won't need to relearn them when you move from one product to the other.

## Using both together

A single company can be connected to **both** an accounting system and eTIMS at once — that's the common case for a Kenyan business: you write an invoice through the Accounting API, and the same invoice is (optionally) submitted to eTIMS for a KRA-signed receipt. The two flows are independent — an eTIMS sale doesn't require an accounting connection, and an accounting invoice doesn't require eTIMS — but [Invoices](/etims-sales) can carry a reference to the matching eTIMS receipt once both have run.

## Still not sure?

- Building expense reports, bill pay, or invoicing for a business **outside Kenya**, or that doesn't need KRA compliance yet? → **Accounting API**.
- Your customer is Kenyan and legally required to issue eTIMS-compliant receipts? → **Compliance API**. You may still want the Accounting API alongside it if they also want their books synced.
