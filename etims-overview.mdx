Sync2Books connects a Kenyan business to **KRA eTIMS** so its invoices carry a valid, KRA-signed
receipt. We hold the eTIMS device credentials, speak the OSCU protocol, own the KRA sequence
numbers and render the compliant receipt. You never certify with KRA, never handle a control
unit, and never call KRA yourself.

<Note>
  **The developer API is being finalised.** eTIMS integration now runs entirely through the
  **Sync2Books Compliance platform** — the dashboard and its own API — rather than through the
  Accounting API. The endpoint reference for the new surface is published when it is stable; see
  [Getting access](#getting-access) below for how to start in the meantime.
</Note>

## Who this is for

You're a developer at a business — or building software for businesses — that invoices in Kenya
and needs eTIMS compliance. Instead of going through KRA certification, device onboarding and
the OSCU specification, the business is onboarded once in the **compliance dashboard**, and your
software then pushes items, stock, sales and credit notes through the **Compliance API**.

## Two surfaces: dashboard and API

Setup is no-code in the dashboard; daily operations are programmatic.

| | **Compliance dashboard** (one-time, no-code) | **Compliance API** (ongoing, programmatic) |
|---|---|---|
| Register the business (KRA PIN, branch, device serial) | ✅ | |
| Initialise the KRA device for a branch | ✅ | |
| Issue and revoke API keys | ✅ | |
| Sync KRA reference data (code lists, item classifications) | ✅ | ✅ |
| Register and sync catalog items | ✅ | ✅ |
| Record stock movements | ✅ | ✅ |
| Issue sales and credit notes | ✅ | ✅ |
| Download and reprint receipts | ✅ | ✅ |
| Monitor submission status and KRA errors | ✅ | ✅ |

In short: **the dashboard handles eTIMS onboarding; your code handles invoicing.** You never have
to script KRA onboarding to get going, and a business that doesn't want to integrate at all can
run entirely from the dashboard.

## How it works

One kind of request — to the Compliance API, with your API key:

```
┌───────────────────┐        ┌──────────────┐        ┌────────────┐
│  Your application │  HTTPS │  Sync2Books  │  OSCU  │  KRA eTIMS │
│  (uses API key)   │ ─────▶ │  Compliance  │ ─────▶ │            │
│                   │ ◀───── │              │ ◀───── │            │
└───────────────────┘        └──────────────┘        └────────────┘
```

Your API key is scoped to one business and one environment — a sandbox key can only address
sandbox businesses, a live key only production ones — so it can never act for another taxpayer
or cross into the wrong eTIMS environment.

## What you'll be doing

The sequence is fixed by KRA's own dependency order, and it's worth knowing before you start:

1. **Register the business and initialise its device** (dashboard). One-time, per branch.
2. **Sync reference data** — KRA's code lists and item classifications. These are the values
   every later submission is validated against, so they're fetched from KRA rather than
   hard-coded. See [Codes & Values](/etims-codes).
3. **Register your catalog.** An item must exist and be registered with KRA before it can be
   invoiced. Goods are stock-tracked; services are not.
4. **Record opening stock** for goods, before you sell them.
5. **Submit sales and credit notes.** Each one is validated, mapped to the OSCU payload, given
   its KRA-owned sequence number, and submitted. A credit note must reference an accepted sale.
6. **Retrieve the receipt** — a TIS-conformant PDF with the KRA verification QR code.

When something is rejected, KRA's own reason comes back with it; see
[Errors & Troubleshooting](/etims-errors).

## Getting access

Access to the Compliance API is per business, by API key issued from the compliance dashboard.
Self-service issuance and rotation in the dashboard UI is being delivered — until it ships, a key
is issued to you by Sync2Books on request, with the same scoping described above.

To get started:

1. **Sign up for the compliance dashboard** and create your organisation.
2. **Add your business** — KRA PIN, branch (`bhfId`), trade address and device serial. For
   production these come from KRA's own onboarding; see
   [eTIMS as a Third-Party Integrator (OSCU)](/ETIMS_OSCU_INTEGRATION_AS_THIRD_PARTY) for where
   each value comes from. Sandbox values are fine while you're building.
3. **Request an API key** for that business, naming the environment you want.
