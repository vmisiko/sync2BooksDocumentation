Several item, sale and credit note fields take **codes**. This page lists the common values so you can fill them in correctly.

> **The good news:** you only ever *must* supply a **classification code**. Everything else has a sensible default or a simple enum.

> The tables below list the common values. For the complete, authoritative lists, read them live: `GET /v1/lookups/code-classes` lists KRA's code groups, `GET /v1/lookups/codes?codeClass=10` returns the codes in one group, and `GET /v1/lookups/classifications` searches item classifications. These endpoints need the `lookups:read` scope. See the [API reference](/etims-api-reference).

## Tax category

Send `taxCategory` (an enum) when you create an item. Sync2Books maps it to the correct KRA tax type automatically — you don't send a tax code yourself. The tax on a sale always comes from the item, never from the sale request.

| `taxCategory` | KRA tax type | Meaning |
|---------------|--------------|---------|
| `VAT_STANDARD` | B | Standard-rated VAT (16%) |
| `VAT_ZERO` | C | Zero-rated (0%) |
| `EXEMPT` | A | Exempt |
| `OTHER` | D | Non-VAT / other |
| `VAT_8` | E | Reduced-rate VAT (8%) |

## Product type

Send `productTypeCode` when you create an item. It is a string, and it selects the KRA product type. Goods (`1` and `2`) are stock-tracked and services (`3`) are not.

| `productTypeCode` | Meaning |
|-------------------|---------|
| `"1"` | Raw Material |
| `"2"` | Finished Product |
| `"3"` | Service |

## Units & packaging

Pass the KRA codes in `unitCode` (quantity unit) and `packagingUnitCode` (packaging unit) when you create an item.

Quantity unit (`unitCode`):

| Code | Meaning |
|------|---------|
| `U` | Pieces / item |
| `KG` | Kilo-gramme |
| `LTR` | Litre |

Packaging unit (`packagingUnitCode`):

| Code | Meaning |
|------|---------|
| `NT` | Net |
| `BL` | Bale |
| `BX` | Box |

> These are the common units. KRA defines many more. List them with `GET /v1/lookups/codes?codeClass=10` for quantity units and `GET /v1/lookups/codes?codeClass=17` for packaging units, and pass the code you choose.

## Payment type (sales)

Send `paymentTypeCode` when creating a sale. It defaults to `01` (cash).

| Code | Method |
|------|--------|
| `01` | Cash |
| `02` | Credit |
| `03` | Cash / Credit |
| `04` | Bank cheque |
| `05` | Debit & credit card |
| `06` | Mobile money |
| `07` | Other |
| `08` | Other |

The live list is `GET /v1/lookups/codes?codeClass=07`.

## Credit note reasons

Send `reason` when you issue a credit note. It defaults to `06`.

| Code | Reason |
|------|--------|
| `01` | Missing quantity |
| `02` | Missing data |
| `03` | Damaged |
| `04` | Wasted |
| `05` | Raw material shortage |
| `06` | Refund |

## Classification code (the one you must look up)

`classificationCode` is the KRA **item classification** (`itemClsCd`) for the product — e.g. `50150000`. Unlike the other codes, **there is no default**: you must supply a valid code before an item can be registered.

- Search valid codes live with `GET /v1/lookups/classifications?query=...`, or browse the **[Item Classification Codes](/etims-item-classification-codes)** reference (or KRA's own list — see [references](#kra-references)).
- Pick the code that best matches the product.
- Once set, the item can be registered and sold.

See [Item Attributes](/etims-item-attributes) for the full item data model this code is part of.

If you try to register an item without one, the call is a `422` with the code `item_incomplete`, and `item.needs.classificationMapping` is `true`.

## Other sale codes

A sale also carries KRA receipt and invoice status codes, such as receipt type `S` for a normal sale and `R` for a credit note. The API sets these for you, so you never send them.

## KRA references

The authoritative, complete code lists are published by KRA:

- **[TIS for OSCU/VSCU Technical Specifications v2.0](https://kra.go.ke/images/publications/TIS-for-OSCU--VSCU-Technical-Specifications-v2.0.pdf)** — all code lists (tax types, units, packaging, product types, payment methods, receipt/invoice status) and the item classification structure.
- See also **[eTIMS as a Third-Party Integrator (OSCU)](/ETIMS_OSCU_INTEGRATION_AS_THIRD_PARTY)** for how these fit the KRA onboarding flow.
